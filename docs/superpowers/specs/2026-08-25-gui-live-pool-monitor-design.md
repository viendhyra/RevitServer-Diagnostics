# Графический интерфейс и живой монитор пулов Revit Server

Дата: 2026-08-25  
Статус: согласованный дизайн

## Цель

Добавить к существующему набору PowerShell-диагностики удобное русскоязычное WPF-приложение для Windows PowerShell 5.1. Приложение позволяет запускать проверку, видеть состояние IIS/Revit Server, вручную применять безопасные исправления, настраивать сбор дампов и наблюдать в реальном времени только за проблемами application pools Revit Server.

Монитор работает исключительно пока открыто окно приложения. Он не устанавливает службу, не добавляет автозапуск, не остаётся в фоне после закрытия окна и никогда не выполняет исправления автоматически.

## Границы первой версии

В первую версию входят:

- графический запуск существующей диагностики;
- сводное состояние IIS, Revit Server и относящихся к нему пулов;
- живой журнал остановок, запусков и аварий пулов;
- обнаружение падений `w3wp.exe` и связанных событий WAS;
- ручной запуск остановленного пула;
- ручное исправление настроек автозапуска и idle timeout;
- ручная установка Rapid-Fail Protection `maximumFailures = 20` без отключения защиты;
- установка и регистрация официального ProcDump с проверкой подписи Microsoft;
- открытие папок отчётов и дампов;
- исправление прямого запуска через `irm | iex`;
- исправление обработки ACL, когда для `NETWORK SERVICE` нет отдельной записи.

Пока не входят:

- мониторинг DNS, NetBIOS, Defender/EDR, DCOM, VSS и остальных смежных ошибок в живом журнале;
- автоматическое исправление обнаруженных проблем;
- фоновая служба, агент в трее или запуск вместе с Windows;
- автоматическая отправка дампов или отчётов;
- анализ содержимого дампа;
- установка или обновление Revit Server.

## Выбранный подход

Интерфейс реализуется на WPF/XAML и запускается в Windows PowerShell 5.1. Это не требует установки PowerShell 7, .NET SDK, веб-сервера или стороннего GUI-фреймворка.

Альтернативы отклонены:

- WinForms проще технически, но хуже подходит для современного масштабируемого интерфейса;
- локальная веб-панель потребовала бы HTTP listener, отдельной модели безопасности и управления жизненным циклом;
- запуск существующего монолитного скрипта дочерним процессом и чтение CSV не даст качественного живого состояния и усложнит обработку ошибок.

Поэтому общая диагностическая логика будет вынесена из сценария командной строки в вызываемые функции. CLI и GUI будут использовать одни и те же функции и возвращаемые объекты.

## Архитектура

### Точки входа

- `RevitServer-Diag.ps1` остаётся консольной точкой входа и сохраняет совместимость существующих параметров.
- `RevitServer-GUI.ps1` создаёт WPF-окно и связывает элементы управления с контроллером приложения.
- `Run.ps1` остаётся безопасным прямым запуском консольной диагностики.
- `Run-GUI.ps1` загружает нужные файлы во временную папку и запускает только GUI.

Файлы прямого запуска сохраняются без BOM, чтобы `Invoke-RestMethod | Invoke-Expression` не превращал U+FEFF в часть имени первой переменной. Остальные русскоязычные PowerShell-файлы сохраняются в UTF-8 BOM для корректного чтения Windows PowerShell 5.1 при запуске с диска.

### Модули

- `src/Diagnostics.psm1` сохраняет низкоуровневые проверки ОС, IIS, Revit Server, событий и обновлений.
- `src/Repairs.psm1` сохраняет операции исправления и отката.
- `src/Reporting.psm1` формирует HTML/CSV/JSON.
- `src/Orchestration.psm1` предоставляет единый вызов диагностики и возвращает структурированный результат без обязательного вывода в консоль.
- `src/PoolMonitor.psm1` классифицирует события пулов, читает состояние IIS и управляет жизненным циклом наблюдения.
- `src/GuiController.psm1` преобразует результаты модулей в модель представления и формирует команды, доступные интерфейсу.

XAML хранится отдельно в `ui/MainWindow.xaml`, чтобы разметка, стили и PowerShell-логика не находились в одном большом файле.

## Интерфейс

Окно использует светлую тему Segoe UI с синими акцентами, карточками состояния и цветами статуса: зелёный — исправно, жёлтый — предупреждение, красный — сбой, серый — нет данных. Интерфейс должен корректно выглядеть при стандартном масштабе Windows 100–150% и минимальном размере 1100×700.

Левое меню содержит пять разделов:

1. **Главная** — имя сервера, версия ОС, состояние IIS/Revit Server, число обнаруженных пулов, активных проблем и время последней проверки.
2. **Проверка** — кнопка полной проверки, прогресс, текущий этап и таблица проблем с фильтром по уровню.
3. **Живой журнал** — состояние мониторинга, таблица событий и кнопки запуска/остановки наблюдения и очистки отображения.
4. **Исправления** — отдельные карточки для запуска пулов, базовых настроек, Rapid-Fail = 20 и ProcDump.
5. **Отчёты** — пути к последнему отчёту и дампам, кнопки открытия папок и HTML-отчёта.

Опасные или изменяющие систему кнопки отмечаются явно и всегда открывают окно подтверждения с точным перечнем планируемых действий. `-Force` не используется GUI по умолчанию.

## Поток диагностики

1. Пользователь нажимает «Запустить проверку».
2. Контроллер создаёт фоновый runspace, чтобы WPF-поток не зависал.
3. Оркестратор последовательно выполняет проверки и публикует события прогресса.
4. GUI обновляет текущий этап и индикатор без блокировки окна.
5. Оркестратор возвращает единый объект результата и создаёт существующие HTML/CSV/JSON-файлы.
6. Контроллер обновляет карточки, таблицу проблем и ссылки на отчёт.

Одновременно разрешён только один полный запуск диагностики. Повторная кнопка блокируется до завершения или отмены. Ошибка отдельной проверки отображается как результат этой проверки и не должна закрывать приложение.

## Живой монитор пулов

После открытия приложения монитор не стартует сам. Пользователь включает его кнопкой «Начать наблюдение».

Монитор объединяет два источника:

- `System.Diagnostics.Eventing.Reader.EventLogWatcher` получает новые события Application/System по провайдерам Application Error, WAS и W3SVC-WP, относящиеся к `w3wp.exe` или пулам Revit Server;
- `DispatcherTimer` раз в 5 секунд читает фактическое состояние только обнаруженных пулов Revit Server и фиксирует переходы `Started`, `Stopped`, `Starting`, `Stopping`, `Unknown`.

События преобразуются в единый объект:

- время;
- уровень `INFO`, `WARN` или `FAIL`;
- пул;
- тип события;
- Event ID и провайдер, если событие пришло из журнала Windows;
- короткое описание;
- технические детали.

Повтор одного и того же состояния без перехода не создаёт новую строку. События Application Error и WAS, относящиеся к одному падению в небольшом временном окне, связываются, но исходные Event ID сохраняются в деталях. Журнал хранит в памяти последние 1000 строк; более старые строки удаляются только из интерфейса. Все новые строки параллельно записываются в CSV текущей сессии.

Закрытие окна или нажатие «Остановить наблюдение» обязательно отключает watchers, timer и обработчики событий. После закрытия приложения мониторинга нет.

## Ручные исправления

GUI показывает только действия, применимые к найденным пулам Revit Server:

- «Запустить остановленные пулы»;
- «Исправить базовые настройки» — AutoStart, `AlwaysRunning`, idle timeout = 0;
- «Установить Rapid-Fail = 20» — меняется только `failure.rapidFailProtectionMaxCrashes`, сама защита остаётся включённой;
- «Настроить ProcDump» — официальный Sysinternals ZIP, проверка Authenticode, полный postmortem dump;
- «Открыть папку дампов».

До изменения показывается список целевых пулов и значений «сейчас → будет». После выполнения состояние перечитывается из IIS. Успех отображается только после проверки фактического значения. Для обратимых изменений используется существующий механизм `Backup_*` и `Rollback.ps1`.

## Исправление текущих дефектов

### BOM прямого запуска

Корневая причина: при `irm <raw-url> | iex` BOM передаётся в строке как символ U+FEFF и становится частью первого токена. `Run.ps1` и новый `Run-GUI.ps1` должны храниться без BOM. Тест проверяет первые три байта обоих файлов и выполняет их содержимое как строку с подменёнными сетевыми/процессными командами.

### Пустой ACL

Корневая причина: при отсутствии совпавшего ACE выражение `$networkService.FileSystemRights` обращается к свойству пустого массива под `Set-StrictMode`. Права собираются через явную итерацию по совпавшим ACE; пустое множество даёт пустую строку и `HasNetworkService = false`. Отдельный тест воспроизводит каталог без совпадающего ACE.

## Ошибки и безопасность

- GUI проверяет запуск на Windows и наличие Windows PowerShell 5.1.
- Для диагностики без изменений допускается запуск без администратора, но недоступные проверки явно помечаются.
- Кнопки изменения системы отключены без прав администратора и объясняют причину.
- Сетевые ошибки загрузки ProcDump не закрывают приложение.
- Дампы никогда не загружаются в интернет и помечаются как потенциально содержащие данные из памяти процесса.
- Если модуль WebAdministration недоступен, GUI показывает ошибку IIS и не предлагает операции над пулами.
- Все действия и ошибки пишутся в журнал сессии.

## Тестирование и критерии готовности

Pester-тесты Windows PowerShell 5.1 должны проверять:

- отсутствие BOM в `Run.ps1` и `Run-GUI.ps1`;
- выполнение текста загрузчика через `Invoke-Expression` без ошибки первого токена;
- безопасную обработку ACL без `NETWORK SERVICE`;
- классификацию событий WAS/Application Error;
- фильтрацию событий, не относящихся к пулам Revit Server;
- удаление дублей состояния и ограничение журнала 1000 строками;
- формирование команд ручного исправления только для целевых пулов;
- Rapid-Fail остаётся включённым и становится равным 20;
- корректную остановку watcher/timer при закрытии окна;
- загрузку и разбор XAML;
- сохранение работы существующей консольной команды и отчётов.

Ручная проверка на Windows Server подтверждает:

- окно открывается из прямой команды GitHub;
- полная проверка не замораживает интерфейс;
- остановка тестового целевого пула появляется в живом журнале не позднее 10 секунд;
- кнопка запуска возвращает пул в `Started` и GUI подтверждает состояние;
- после закрытия окна в системе не остаются PowerShell-процесс, watcher или таймер приложения;
- обычное открытие GUI и диагностика ничего не изменяют.

## Команды запуска

Консольная диагностика:

```powershell
irm https://raw.githubusercontent.com/viendhyra/RevitServer-Diagnostics/main/Run.ps1 | iex
```

Графический интерфейс:

```powershell
irm https://raw.githubusercontent.com/viendhyra/RevitServer-Diagnostics/main/Run-GUI.ps1 | iex
```
